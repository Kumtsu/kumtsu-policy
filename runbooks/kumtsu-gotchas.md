# คลัง gotchas: กับดักที่เจอจริง รวมจากทุก runbook (Kumtsu)

อัปเดต 29 ก.ย. 2569 (เพิ่มข้อควรระวัง 1 ต.ค. และหมวด Antigravity/CLI 12 พ.ย. 2569) · อ่านก่อนลงมือทุกงาน · รายละเอียดเต็มอยู่ใน runbook ที่ระบุในวงเล็บ · เจอกับดักใหม่ให้เพิ่มที่นี่ (บอกวันที่ + ที่มา)

## 1. รีพอร์ตยอดขายรายวัน (kumtsu-daily-sales-report)
- สูตรที่มี `$` ต้องตรวจทุกตัวหลังคัดลอกบล็อกแบรนด์ (แถว PERCENTAGE หารผิดแถวอยู่ 7 วัน 18–24 ก.ย.)
- `report!B355` ฝังชื่อคอลัมน์ไว้ในสตริง แทรกคอลัมน์แล้วไม่ขยับ หน้า By Brand พังทั้งหน้า
- ห้ามแตะ `brands!A14` (ชื่อกลุ่มเมนูของ FoodStory = คีย์) · เปลี่ยนชื่อแบรนด์ที่ B14 เท่านั้น
- By Brand ต้องกัน Training/Marketing/Add Waste ทุกคอลัมน์ · เดือนใหม่ต้องเช็ก `DE3`
- ห้ามใส่สูตรสำรวจ MAKEARRAY+FORMULATEXT+INDIRECT ในไฟล์จริง (ไฟล์คำนวณล้มถาวร) · ห้ามกด "รีเซ็ต" ตัวแบ่งหน้า · ห้ามวาง/แทรกโดยไม่ตรวจว่าแทรกสำเร็จ
- พิมพ์ลงเซลล์ตรง ๆ ตัวอักษรแรกหาย · autocomplete เติมเอง (กด Delete ก่อน Enter) · `Cmd+R` ในชีตคือรีโหลดหน้า
- ปุ่ม export CSV ของ FoodStory เปลี่ยน UI แล้ว ต้องคลิกเมาส์จริง 2 ครั้ง ไม่ใช้ `.click()` ของ JS
- งานไม่เสร็จจนเห็นอีเมลครบ 2 ฉบับใน Sent

## 2. FoodStory: เพิ่มสินค้า/deploy (kumtsu-add-inventory-item, kumtsu-skills-foodstory)
- แม่แบบต้องมีแค่ "ของใหม่" ห้าม deploy ทั้งหมด (บทเรียน 14 ก.ย.)
- ห้ามติ๊ก "อัปเดตราคาวัตถุดิบ" (ทับราคาสาขา) · "ลบข้อมูลเก่า" ต้องเป็น "ไม่ลบ" (ไม่งั้นล้างสต็อกสาขา)
- ห้ามตัดแถวเดิมออกจากชีต 1 ตอนนำเข้า (ชีต 3 อ้างกลับ) · นำเข้าใช้โหมด "เก็บข้อมูลปัจจุบันไว้"
- ส่งออกไฟล์ใหม่เสมอ ห้ามใช้ไฟล์เก่า · เช็ก 3 อย่างก่อนเริ่มทุกครั้ง (มีคนอื่นแก้ระบบเดียวกัน)
- "นำไปใช้ไม่สำเร็จ" ไม่ได้แปลว่าของไม่ถึงสาขา ตรวจที่ปลายทาง · กล่องเลือกสินค้าห้ามคลิกพิกัดตายตัว
- ฝั่งกรองของ `data inventory_price_sup` มีสูตร ห้ามพิมพ์ทับ · ตรวจรหัสซ้ำใน master ก่อนทำไฟล์นำเข้า · แท็กเนื้อสัตว์มี 2 อัน (พิมพ์ ื เกิน)
- ห้ามเดาขั้นตอนบนหน้าจอที่ยังไม่บันทึก (สูตรตัดสต็อกผิดทั้งแบรนด์)
- login ต้อง reCAPTCHA ห้ามกดแทน ห้ามกรอกรหัสผ่าน · session หมดอายุบ่อย

## 3. COGS / Inventory (kumtsu-monthly-cogs, kumtsu-inventory-cogs-log)
- มูลค่า = จำนวนจากข้อมูลดิบ × ราคาจาก `master data inv new` ห้ามใช้ราคา FoodStory หรือคอลัมน์ต้นทุนส่วนผสมใน BOM
- EM (เครื่องมือ) ไม่นับเป็นวัตถุดิบ · โปรตีนไม่ได้อยู่ในสูตรหลัก
- กฎ +1 วัน: สต็อกของวันนี้พนักงานคีย์วันพรุ่งนี้ · วัดความครบด้วยแถวที่ `จำนวนที่ตรวจนับ <> 0` ไม่ใช่จำนวนแถว
- `raw data Open stock` มี 327 แถวครัวกลาง HO ไม่มีวันที่ ตรวจก่อนกรองแถวว่าง
- ห้ามแตะไฟล์เดือนก่อน (จด modifiedTime ก่อนเริ่ม) · ยกยอดปิดงวดเดือนก่อนเป็นต้นงวดเดือนนี้ (ห้ามลบ)
- ยอดขายสองแหล่งไม่ตรง (fact_sales_line 24.69M/52 สาขา vs report 22.84M/45 สาขา) ต้องกระทบก่อนใช้เป็นตัวหาร · เกณฑ์ใหม่สูงกว่าเกณฑ์เดิม ~3.3%
- ชื่อสาขาไทยห้ามพิมพ์เอง (สระ/วรรณยุกต์สลับ จับคู่ไม่ติด) ใช้รหัสแฮช/ค่าจากแถวหัวตาราง · `parseFloat("1,250")` ได้ 1
- ล้างสูตรที่ถูกแก้มือค้างจากเดือนก่อนทุกเดือน (Phase 6b) · หัวตาราง `cogs by BRANCH` แถว 1 ต้องแก้มือ

## 4. ไฟล์ REV ของบัญชี (acc-rev-platforms-file)
- รวมรายสาขาให้ group by คอลัมน์ FOODSTORY เสมอ ห้าม group ด้วยชื่อร้านแพลตฟอร์ม
- ช่อง TOTAL GP ขึ้น #VALUE! · อัตรา Robinhood ในไฟล์เดียวกันไม่ตรง (22.00 vs 21.91) · ชื่อแท็บ "ADS Montly" สะกดผิด

## 5. เงินเดือน / ค่าเช่า (runbook-payroll-branch-mapping, runbook-branch-rent-utilities)
- ห้ามบวกคอลัมน์ค่าอาหาร/เบี้ยขยันทั้งหมด (ยอดเบิ้ล) ใช้ J และ BT เท่านั้น
- ไฟล์ค่าเช่ามีข้อผิดพลาดที่เจอซ้ำ ตรวจทุกเดือน (ดู runbook)

## 6. Supabase / ข้อมูล
- ห้ามโหลดข้อมูลแพลตฟอร์ม/COGS ของแฟรนไชส์เข้า `branch_month_fact`
- `sales_brand` เป็นมุมมองซ้ำ (sign=0) ห้ามรวมซ้ำ · ยอดขายเก็บหลัง VAT ให้ view หัก 7/107
- ห้ามแตะ `brands.code` และ `products.group_name/category_name`
- ผลลัพธ์ SQL/Drive ที่ยาวเกินจะถูกตัด (Drive อ่านชีตได้ ~150–190 แถว) ตรวจว่าอ่านครบก่อนสรุป

## 7. เครื่องมือ / การทำงาน
- อัปโหลด Drive ผ่าน base64 ได้เฉพาะไฟล์เล็ก · markdown → Google Doc ทำ & เพี้ยนและมีแถวหัวตารางว่าง
- GitHub: ทดสอบด้วย SSH เสมอก่อนสรุปว่ายังไม่ push (HTTPS ให้ผลผิด) · fetch เทียบก่อน push
- osascript clipboard segfault เมื่อไฟล์เกิน ~1.5MB
- ห้ามรายงานว่าเสร็จจนกว่าจะตรวจ (verification-before-completion)


## ข้อควรระวังเพิ่ม (1 ต.ค. 2569)
- RLS ไม่คุมคำสั่ง TRUNCATE → ตารางที่เปิด RLS ต้องถอนสิทธิ์ TRUNCATE จาก authenticated ด้วย
- views v_branch_pl, v_branch_brand_sales, v_company_pl เป็นของ postgres และเป็น SECURITY DEFINER จึงข้าม RLS ของตารางฐาน ถ้าเปลี่ยนเป็น security_invoker ต้องมี policy อ่านครบก่อน
- ตาราง branch_master, branch_alias, pl_line, branch_month_fact ไม่มีคอลัมน์ organization_id → policy ใช้สิทธิ์ dashboard.view อย่างเดียว
- ส่วนลดและราคาโปรฝั่งแพลตฟอร์ม (เช่นราคา 89 บาท) ไม่อยู่ใน FoodStory (discount ใน POS ≈ 0) ดูราคาโปรจากข้อมูล POS ตรง ๆ ไม่ได้
- ชื่อเมนูใน fact_sales_line ฝังไซส์และตัวเลือกไว้ในชื่อ (Size M / XL / Jumbo) การแยกไซส์ต้องจับคำจากชื่อ ตัวเลขเป็นค่าประมาณ

## 8. การทำงานบน Antigravity, Chrome DevTools และ CLI (12 พ.ย. 2569 — kumtsu-antigravity-log)
- **CLI Credential Proxy (`gmail`, `gsheets`, `gdrive`):** ต้องเรียก CLI เป็นคำสั่งระดับบนสุด (top-level command) เท่านั้น ห้ามห่อใน `python3 subprocess` และห้ามต่อคำสั่งหลาย CLI ด้วย `&&` ไม่งั้น proxy จะไม่ inject credential และขึ้น `no credentials found`
- **Chrome Remote Debugging (`--autoConnect` ที่ `127.0.0.1:9222`):** ใช้ session Chrome โปรไฟล์ Mister Bobby ที่ผู้ใช้เปิดและล็อกอิน FoodStory ค้างไว้ (ตามนโยบายฉบับ 14 ห้ามกรอกรหัสผ่านหรือกด CAPTCHA แทนคน) และก่อนปิดแท็บหลังจบงานต้องเรียก `list_pages` เพื่อปิดเฉพาะแท็บที่เปิดเอง ห้ามแตะแท็บเดิมของผู้ใช้
- **Google API แทนการคัดลอกผ่าน Clipboard/UI:** `gsheets mutate raw-batch` (`pasteData` TSV) วางข้อมูลหลายพันแถว (ยอดขาย 8,586 แถว / GR 7,993 แถว) ได้รวดเดียวปลอดภัยกว่า clipboard, `gdrive mutate upload --parent <folderID>` อัปโหลดไฟล์เข้า Drive ได้ตรง และ `gmail mutate create-draft` บน Antigravity CLI รองรับ `--to` หลายคนคั่นด้วย comma พร้อมแนบหลายไฟล์ (`--attach`) ในคำสั่งเดียว
- **FoodStory DataTables & Sandbox Boundary:** บน FoodStory ปุ่ม UI ที่คลิกติด timeout (`Failed to interact`) คุมได้ผ่าน `DataTable().page.len(5000).draw()` / `jQuery.ajax('/api/setDate')` · ส่วน MCP `chrome-devtools` `evaluate_script` argument `filePath` ไม่สามารถเขียนลงนอก root workspace (`Access denied`) ให้ส่ง JSON ขนาดพอดีกลับจาก JS หรือย้ายไฟล์ที่ดาวน์โหลดจาก `~/Downloads` เข้า `scratch/` แล้วลบทิ้งเมื่อส่งงานเสร็จ
- **ตรวจนโยบายและสุขภาพห้องปิดท้ายเสมอ:** นโยบายกลาง (`kumtsu-master-policy`) อาจอัปเดตระหว่างทำงาน (เช่น 12 พ.ย. ออกฉบับ 15 ระหว่างปิดรอบ) จึงต้องตรวจ `public.ops_room_health` ทั้งก่อนเริ่มและหลังปิดงาน และซิงก์สำเนาใน `~/.gemini/` กับ `~/All Ai/antigravity/` ให้ MD5 ตรงกันทุกไฟล์
- **แยก Dashboard 2 ตัวของคุ้มสึให้ถูก (12 พ.ย. 2569 เช้า — `ops_logbook #408`):** `kumtsu-sales-dashboard.vercel.app` ดึงจาก Supabase (`fact_sales_daily`) และซิงก์จาก Google Sheet ผ่าน Vercel cron อัตโนมัติ (ทำงานปกติทุกห้อง, ต้องล็อกอิน) ส่วนหน้าอ่านเร็วในอีเมล (`claude.ai/artifact/MXokuCw9ibzUhyVLrfFK9e`) เป็นไฟล์ `dash/exec.html` ที่ Antigravity สร้างในเครื่องได้ครบแต่กด publish ขึ้น Claude Artifact โดยตรงไม่ได้
- **ความแม่นยำของบทวิเคราะห์ในอีเมลยอดขาย (ผลตรวจข้ามห้อง `ops_logbook #406`):** ห้ามระบุเป็นข้อเท็จจริงว่าแคมเปญโปรโมชัน (เช่น 11.11) เป็นสาเหตุที่แพลตฟอร์มโต เพราะข้อมูล POS ไม่เห็นราคาโปรหรือส่วนลดฝั่งแพลตฟอร์ม (ให้แยกเป็นสมมติฐาน) · ตรวจนับจำนวนวันต่อเนื่องกับตารางจริงก่อนเขียนเสมอ (เช่น `< 120,000` ของ ShopeeFood ช่วง 9–10/11 คือ 2 วัน ไม่ใช่ 3 วัน) · และตรวจแหล่งอ้างอิงตัวเลขเศรษฐกิจภายนอกเองทุกครั้งก่อนส่งอีเมล

## 9. GrabMerchant Portal (`kumtsu-grab-portal`, `runbook-grab-portal-finance` · 12 พ.ย. 2569)
- **กับดัก VAT ช่อง `[57]` ใน CSV 68 คอลัมน์ของ Grab คิดคนละแบบระหว่าง `ชำระเงิน` กับ `โฆษณา`:** ในแถว `ชำระเงิน`, ค่าคอมมิชชันและค่าการตลาด (`[44]+[46]+[47]+[48]`) **รวม VAT 7% ไว้แล้ว** ช่อง `[57]` เป็นเพียง Memo แยกแสดงภาษี (ห้ามนำมาลบซ้ำ ไม่งั้น `[52] ทั้งหมด` จะผิด) แต่ในแถว `โฆษณา` ช่อง `[29] ยอด` เป็นยอด **ก่อน VAT** และ `[52] ทั้งหมด` จะบวก VAT `[57]` เข้าไปอีก 7%
- **หน้า `การจ่ายรายได้` (`finances?page=st`) และ API `settlements` กรองตามวันเงินโอนเข้าบัญชี (T+1 เวลา ~02:00–03:39 น.) ไม่ใช่วันขาย:** ยอด `page=st` วันที่ 11 พ.ย. (`416,278.87`) คือยอดขายของวันที่ 10 พ.ย. ส่วนยอดขายวันที่ 11 พ.ย. (`437,996.43`) จะโอนเข้าบัญชี Kasikornthai ในวันที่ 12 พ.ย. (`437,992.74`)
- **อ่านรายงาน Excel GMFR (`GrabMerchant_Reports_*.xlsx`) ด้วย Python `openpyxl`:** ต้องเปิดด้วย `read_only=False` เสมอ หากใช้ `read_only=True` แท็บ `สรุป` จะอ่านออกมาว่างเปล่า (ไม่มี `dimension` ref) และรายงาน GMFR พร้อมให้ดาวน์โหลดเฉพาะวันปิดยอดย้อนหลัง (`T-1` ขึ้นไป)
- **ไม่เทียบยอด Grab Portal กับ FoodStory (`fact_sales_daily`) ตรง ๆ:** วันเดียวกัน (11 พ.ย. 2569) Grab Portal ปิด `2,690` ออเดอร์ `631,281` บาท ส่วน FoodStory บันทึก `2,771` บิล `645,765` บาท เพราะสาขาแฟรนไชส์ ออเดอร์ยกเลิก และกติกาบันทึกส่วนลดต่างกัน ต้องทำกระทบยอดรายสาขาแยกต่างหาก
