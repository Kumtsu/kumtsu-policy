# คู่มือล็อกบุ๊คกลางรายเดือน (kumtsu-monthly-logbook)

ฉบับที่ 1 · 27 ต.ค. 2569 · เจ้าของ: คุณบ๊อบบี้ · ops_logbook #143
ฉบับหลักอยู่ที่ Supabase `public.runbooks` slug **`kumtsu-monthly-logbook`** ใช้คู่กับนโยบายกลางข้อ 4.7

**ใครอ่าน:** AI ทุกห้อง (ส่วน B) และห้อง KUMTSU DEV หรืองานอัตโนมัติที่ปิดและเปิดเล่มทุกวันที่ 1 (ส่วน C)

## ภาพรวม
- ล็อกบุ๊คกลาง (`public.ops_logbook`) แบ่งเป็น **เดือนละ 1 เล่ม** ชื่อเล่มใช้ปี พ.ศ. เช่น `2569-10` และ `2569-11`
- ข้อมูลยังอยู่ในตารางเดียว แต่ **ทุกห้องอ่านจาก view `ops_logbook_current`** ซึ่งแสดงเฉพาะเล่มเดือนนี้กับงานที่ยังค้างจากเดือนก่อน แถวที่ต้องอ่านจึงไม่โตตามเวลา
- งานค้างยกไปเล่มใหม่เองอัตโนมัติ (view แสดงงานที่ status เป็น todo, in_progress หรือ blocked และใส่ `carried_over = true`) **ไม่ต้องสร้างแถวซ้ำ**
- วันที่ 1 ของทุกเดือน ปิดเล่มเก่าด้วย **รายงานกิจกรรมประจำเดือน** เพื่อให้รู้ว่าทั้งเดือนบริษัททำอะไรไปบ้าง ได้ผลอะไร อะไรยังติด และใช้เป็นตัวขับเคลื่อนธุรกิจในเดือนถัดไป
- ถ้าวันหนึ่งข้อมูลถึงหลักแสนแถว ค่อยแยกตารางจริงรายเดือน (partition) โดยห้องอื่นไม่ต้องแก้อะไร

---

## A. view ที่ใช้
| view | ใช้ทำอะไร |
|---|---|
| `ops_logbook_current` | เล่มเดือนนี้ + งานค้าง มีคอลัมน์ `book` และ `carried_over` เพิ่มจากตารางเดิม |
| `ops_logbook_month_summary` | สรุปต่อเล่ม ต่อหมวด: total, done, open, blocked, cancelled, decisions, owners, first_id, last_id |
| `ops_logbook_month_by_room` | สรุปต่อเล่ม ต่อห้อง (จาก tag `room:`): total, done, open |

ทั้ง 3 ตัวใช้ `security_invoker` สิทธิ์การมองเห็นจึงเหมือนตารางเดิม

---

## B. กฎของทุกห้อง (ทำทุกวัน)
1. **อ่าน** งานจาก `ops_logbook_current` เท่านั้น ห้ามดึงทั้งตาราง ถ้าต้องดูย้อนหลัง ให้กรอง `log_date` เป็นช่วงที่ต้องการ
   ```sql
   select id, log_date, category, title, status, result
   from public.ops_logbook_current
   where 'room:<ชื่อห้อง>' = any(tags)
   order by carried_over desc, id desc;
   ```
2. **เขียน** ลง `public.ops_logbook` เหมือนเดิมทุกอย่าง (กฎข้อ 4.1–4.6) และต้องมี tag `room:` ทุกแถว ไม่งั้นรายงานปิดเล่มจะจัดเข้าห้องไม่ได้
3. **งานค้าง** ไม่ต้องสร้างแถวใหม่ตอนขึ้นเดือน ให้แก้แถวเดิมเมื่อเสร็จ (status = `done` + result)
4. **รับทราบเล่มใหม่:** งานแรกของห้องในเดือนใหม่ ให้ตรวจว่ามีประกาศ `logbook_open` ของเล่มนั้นแล้ว จากนั้นลงแถวรับทราบ 1 แถว
   ```sql
   -- ดูประกาศเล่มล่าสุด
   select id, title, result from public.ops_logbook
   where 'logbook_open' = any(tags) order by id desc limit 1;
   ```
   แถวรับทราบ: category `data_system` · status `done` · title `รับทราบล็อกบุ๊คเล่ม <เล่ม>` · tag `logbook_ack`, `book:<เล่ม>`, `room:<ชื่อห้อง>` · summary บอกว่าห้องมีงานค้างยกมากี่งาน (#อะไรบ้าง)

## C. ปิดเล่มเก่าและเปิดเล่มใหม่ (วันที่ 1 ของทุกเดือน 06:00)
ทำโดยงานอัตโนมัติประจำเดือน หรือห้อง KUMTSU DEV ถ้างานอัตโนมัติไม่ทำงาน

**C1. ดึงตัวเลขของเล่มที่ปิด** (แทน `<เล่ม>` เช่น `2569-10`)
```sql
select * from public.ops_logbook_month_summary where book = '<เล่ม>' order by total desc;
select * from public.ops_logbook_month_by_room where book = '<เล่ม>' order by total desc;
select id, category, title, status, result from public.ops_logbook
where (extract(year from log_date)::int + 543)::text || '-' || to_char(log_date,'MM') = '<เล่ม>'
  and ('decision' = any(tags) or status in ('todo','in_progress','blocked'))
order by status, id;
```

**C2. เขียนรายงานกิจกรรมประจำเดือน** ตามแบบฟอร์มส่วน D เก็บเป็น runbook slug `kumtsu-logbook-<เล่ม>` (เช่น `kumtsu-logbook-2569-10`) และลงไฟล์ `/mnt/project-files/logbook/ล็อกบุ๊ค-<เล่ม>.md` กับ Drive โฟลเดอร์ KUMTSU MODEL AI CLAUDE

**C3. ประกาศเปิดเล่มใหม่** ลง ops_logbook 1 แถว
- category `data_system` · title `เปิดล็อกบุ๊คเล่ม <เล่มใหม่> · ปิดเล่ม <เล่มเก่า>`
- tag `logbook_open`, `book:<เล่มใหม่>`, `room:KUMTSU DEV`
- result: ยอดเล่มเก่า (ทั้งหมด / เสร็จ / ค้างยกมา) และชื่อ runbook รายงาน
- related_runbook `kumtsu-logbook-<เล่มเก่า>`

**C4. แจ้งคุณบ๊อบบี้** สรุป 3 บรรทัด: ยอดงาน ผลเด่น และเรื่องที่ต้องตัดสินใจ พร้อมชื่อรายงาน

**C5. ตรวจการรับทราบ** วันที่ 7 ของเดือน
```sql
select substr(t,6) as room, max(id) as ack_id
from public.ops_logbook, unnest(tags) t
where t like 'room:%' and 'logbook_ack' = any(tags) and 'book:<เล่มใหม่>' = any(tags)
group by 1;
```
ห้องที่ยังไม่อยู่ในผลลัพธ์ ให้แจ้งคุณบ๊อบบี้

## D. แบบฟอร์มรายงานกิจกรรมประจำเดือน
```
# ล็อกบุ๊คเล่ม <เล่ม> · รายงานกิจกรรมประจำเดือน

## 1. ภาพรวม
- งานทั้งหมด <n> · เสร็จ <n> · ค้างยกไป <n> · ยกเลิก <n> · การตัดสินใจ <n>
- แผนกหรือห้องที่มีงานมากสุด 3 อันดับ
- เทียบเล่มก่อน: เพิ่ม/ลดกี่งาน

## 2. งานแต่ละแผนก (ตามหมวดและห้อง)
| หมวด/ห้อง | ทั้งหมด | เสร็จ | ค้าง | งานเด่น |

## 3. ผลลัพธ์ที่ส่งผลต่อธุรกิจ
งานที่ลดต้นทุน เพิ่มยอดขาย ลดเวลา หรือแก้ปัญหาซ้ำ (อ้าง # ทุกข้อ)

## 4. การตัดสินใจของเดือน
| # | เรื่อง | ใครตัดสิน | ผล |

## 5. งานค้างยกไปเล่มใหม่
| # | เรื่อง | ห้อง | ค้างเพราะ / รอใคร |

## 6. คุณภาพการบันทึก
แถวที่ไม่มี tag room: · ห้องที่ไม่ได้ลงบันทึกเลย · ห้องที่ยังไม่รับทราบนโยบายฉบับล่าสุด

## 7. ข้อสังเกตและข้อเสนอสำหรับเดือนหน้า
มองแบบ "พลิกวิกฤตให้เป็นโอกาส": ปัญหาที่เกิดซ้ำ งานที่ควรทำเป็นสกิลหรืองานอัตโนมัติ และงานที่ควรเร่ง (3–5 ข้อ)
```
